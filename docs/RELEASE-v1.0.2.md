# v1.0.2 账户余额恢复

本版修正把“主聊天 Key 访问”和“DSH 账户余额”一并禁用的问题。账户余额只调用宿主账户服务，不解析登录令牌、不自行请求账户后台、不读取主聊天 API Key，也不在账户失败时转用 Key。

| 能力 | 当前策略 |
| --- | --- |
| DSH 账户余额（含同币种赠金） | 开启 |
| 本地账本、用量记录、预警、预算与校正 | 开启 |
| AI 插话和独立插件 API | 保留原有配置及隐私检查 |
| 主聊天 Key 余额、旧凭据编辑、自动探活 | 禁用 |
| Codex 日志扫描、会话标题跟踪 | 禁用 |

账户余额来自 DSH 登录服务；其内部仍需要宿主自己的认证，不代表余额查询完全没有认证或网络请求。插件只向前端返回规定的余额字段，不转交服务返回的额外字段。

## 更新与使用

1. 下载 v1.0.2 源码包，保留自行准备的角色、气泡和音效素材。
2. 通过当前 DSH 版本的本地插件安装功能，将实际使用的 profile 更新到这个源码目录。不要同时安装原版和改版到同一 profile。
3. 完全退出并重新启动 DSH，浏览器版同时刷新页面。菜单应显示 `v1.0.2`。
4. 在 DSH 的账户设置登录 DeepSeek，再刷新挂件余额。无需在挂件里填写主聊天 Key 或旧余额凭据名。
5. 插话继续使用“插件 API → 配置 API”。账户余额和插话 Key 分开；DeepSeek 选择官方预设 `https://api.deepseek.com`。

本版允许精确官方域名 `api.deepseek.com` 使用 TUN 代理的 `198.18/15` 映射，并保留 HTTPS 443、证书及域名校验。私网/回环和自定义域名 Fake-IP 仍拒绝。仅设置 `HTTP(S)_PROXY` 环境变量的代理方式仍不受支持。

没有账户服务、未登录或钱包不可用时会显示具体状态，不会启动凭据读取。没有稳定账户 ID 时只显示余额，暂停余额差记账，避免把不同人的余额记在同一基线上。账户切换期间返回的旧查询结果会被丢弃。超时后复用尚未完成的宿主查询，避免重复积累网络工作。

账本沿用原有账户与币种结构，历史记录不自动删除。消费记录仅含金额、时间、模型和 Token；模型 ID 有长度与格式限制，原始对话及标题不会被本轮恢复的记账功能写入。预警文字和气泡样式属于用户主动保存的显示设置。账本写入失败时保留余额但隐藏不可靠统计与校正入口。

## 验证边界

运行 `npm test`（或 `node --test tests/*.test.mjs`）。测试会启动真实插件注册流程、调用实际路由，使用隔离的模拟宿主账户、凭据调用陷阱和临时账本。覆盖账户/赠金汇总、失败不回退 Key、账户切换、无稳定 ID、迟到回复、超时并发控制、写入失败、账本字段白名单、配置保存、旧凭据操作拦截与同源/宿主认证。

自动化回归共 **31 项通过**，不使用真实 Key、不调用付费模型、不修改实际 DSH 数据。

2026-10-15 另经用户授权，对当前 `CompanionApi` 与 `secureJSON` 实现做了一次真实联网验证：官方模型列表返回 2 个模型，`deepseek-flash` 回复 `OK`；聊天仅调用一次，服务端报告输入 11、输出 1、合计 12 Token。Key 通过不回显的标准输入送入内存凭据，未写入文件；此验证没有覆盖 Windows 密钥持久化或页面操作。

此交付没有远程接管反馈者电脑，也没有证明其宿主版本、代理或真实账户服务均正常。插话 Key 仍使用原来的 Windows DPAPI 存储；账户余额与此初始化互不依赖。API Key 可验证插话，不能替代 DSH 账户登录服务验证账户余额。
